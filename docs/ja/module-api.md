# Polynya モジュール API

[English](../module-api.md) · [Русский](../ru/module-api.md) · [简体中文](../zh/module-api.md) · **日本語**

Polynya のモジュールは、どの言語で書いてもよい独立したプログラムです。Node.js や Python のスクリプト、`.exe`、PowerShell スクリプトなどが使えます。モジュールは専用のフォルダーにマニフェスト `module.toml` と一緒に置かれ、`stdin`/`stdout` を通じて JSON 行でコアとやり取りします。

UI を描くのはコアです。モジュールが送るのはデータだけです。行で構成された画面、通知のチップ、コピーするテキストなどです。アイランドはそれをタスクバーのスタイルで描画し、テーマ、アニメーション、キーボード操作、IME 入力も受け持ちます。モジュールには UI フレームワークが不要で、タスクバーの位置や色を知る必要もありません。モジュールがクラッシュしてもアイランドは動き続け、何が起きたかを表示します。

このページはリファレンスです。ゼロから作る完成したモジュールは **[サンプル](module-examples.md)** を参照してください。

---

## 1. フォルダーとインストール

```text
%LOCALAPPDATA%\Polynya\modules\<id>\
├── module.toml
└── main.js            （または main.py、tool.exe など）
```

ポータブル版では、モジュールのフォルダーは `polynya.exe` の隣の `modules\<id>\` で、ログも同じ場所の `logs\` にあります。

* **インストール：** フォルダーを `modules\` に置きます。次に検索を開いたときにコアが読み込むので、再起動は不要です。コードを変更した後に動作中のモジュール プロセスを再起動するには、`polynya modules reload` を実行します。
* **オン／オフ：** アイランドの設定の「モジュール」で切り替えます。変更はすぐに反映されます。
* **削除：** フォルダーを削除します。
* **問題**（壊れたマニフェスト、インタープリターが見つからない、クラッシュ）は、タスクバーのチップとログ `%LOCALAPPDATA%\Polynya\logs\polynya.log` に表示されます。

## 2. マニフェスト：`module.toml`

```toml
api = 1                      # プロトコルのバージョン。コアが知らない新しいバージョンは拒否される
id = "devtools"              # 一意の id：ラテン文字、数字、- と _
exe = "main.js"              # 実行するもの。「モジュールの起動方法」を参照
args = ["--fast"]            # 省略可：コア自身の引数の前に置く引数
kind = "search"              # 省略可：search | zone | other
name.en = "Devtools"         # モジュールの名前。言語ごとに指定（なければ en）
name.ja = "開発ツール"

resident = false             # アイランドの起動時からプロセスを動かし続ける
hooks = false                # オン／オフ時に `exe register` / `exe unregister` を呼ぶ
taskbar = false              # タスクバーが横向きのときだけ動かす
experimental = false         # ユーザーが有効にするまでオフ

[main]                       # 省略可：検索に出すモジュール本体。メイン画面を開く
hint.ja = "Web ツール"
keywords = ["devtools", "px", "rem"]
icon = "m18 16 4-4-4-4 | m6 8-4 4 4 4 | m14.5 4-5 16"

[[functions]]                # 省略可：メイン画面の機能。検索とホットキーで使える
id = "convert"               # モジュールが `invoke` で受け取る値
title.en = "Convert value"   # モジュールのメニューでの項目名とまったく同じ
title.ja = "値を変換"
hint.ja = "単位、色"
keywords = ["convert", "px", "rem"]
icon = "M8 3 4 7l4 4 | M4 7h16 | m16 21 4-4-4-4 | M20 17H4"
hotkey = "Ctrl+Alt+D"        # 省略可：グローバル ホットキー
selection = true             # 省略可：ホットキーで選択中のテキストを送る
search = true                # 省略可：false なら検索に出さない（ホットキーとメニューのみ）
```

**言語別の文字列**（`name`、`title`、`hint`）は、普通の文字列か、言語ごとのテーブル（`ru`、`en`、`zh`、`ja`）で書きます。該当する言語がなければ `en` が使われます。

### メイン画面とその機能

モジュールは 1 つの画面を持つ 1 つのまとまりです。検索、ホットキー、メニューはそこへの入口が違うだけで、別々の機能ではありません。

* **`[main]`** はモジュールそのものを、その `name` で検索に追加します。選ぶと `main` が実行され、モジュールはメイン画面を開きます。画面を持たないモジュール（フックやチップだけ）には `[main]` はありません。
* **`[[functions]]`** は、メイン画面の項目のうち直接呼び出せると便利なものです。**どの機能にも、モジュールの画面に同じ `title` の対応する項目がなければなりません。** 検索では「開発ツール › 値を変換」のように、メニュー内の同じ項目への道筋として表示され、モジュール名はコアが付け足します。画面にないものを機能にすることはできません。コアはこれを確認できないので、API のルールとして定めています。
* **メニューでは**、機能の行に `"command": "convert"` を付けます（[画面](#5-画面) を参照）。コアはその行に、ユーザーが設定したとおりの機能のホットキーを表示し、行が選ばれると `"source": "menu"` の `invoke` を送ります。機能はどこから呼ばれても同じ形で届き、何から始めるかはモジュールが `source` を見て決めます。

**検索の照合はコアが行います。** 検索欄の文字列を、すべての言語の名前（機能なら「モジュール名 + 名前」も）と `keywords` に同時に照合し、何かが選ばれるまでモジュールのプロセスは起動しません。

**ホットキー**（`[main]` または機能に指定）は修飾キーとキーの組み合わせで書き、大文字と小文字は区別しません。例：`Ctrl+Alt+D`、`Ctrl+Shift+F2`、`Win+Alt+Space`。`Ctrl`、`Alt`、`Shift`、`Win` のうち少なくとも 1 つが必要です。キーには英字、数字、`F1`–`F24`、`Space`、`Enter`、`Tab`、`Insert`、`Home`、`End`、`PageUp`、`PageDown`、または `` ` - = , . / ; `` のいずれかを使えます。ほかのアプリが使用中のホットキーはスキップされ、ログに 1 行記録されます。ユーザーは `config.ini` で任意のホットキーを変更したり無効にしたりできます。

```ini
hotkey.devtools.convert = Ctrl+Shift+Q
hotkey.devtools.convert =
```

1 行目は `Ctrl+Shift+Q` を割り当て、値が空の 2 行目はホットキーを無効にします。`[main]` のキーは `hotkey.<モジュール>.main` です。

**アイコン**は 24×24 グリッド上の SVG パスで、Lucide スタイルの 1 本の線で描かれます。複数のサブパスは `|` で区切ります。使えるコマンドは `M L H V C S Q T A Z` で、大文字と小文字のどちらも使えます。

エラーのあるマニフェストはスキップされ、理由がログとチップに表示されます。例：`devtools: manifest: id = "a b": use only latin letters, digits, - and _`。`title` のない機能もエラーになります。

## 3. モジュールの起動方法

コアはモジュールのフォルダーを作業ディレクトリにして `exe [args] run` を実行します。

| `exe` | 実行されるもの |
| :--- | :--- |
| `main.js`、`.mjs`、`.cjs` | `node main.js run` |
| `main.py`、`.pyw` | `py -3 main.py run`（`py` ランチャーがなければ `python`） |
| `main.ps1` | `powershell -NoProfile -ExecutionPolicy Bypass -File main.ps1 run` |
| フォルダー内のファイル | そのファイル |
| それ以外 | `PATH` 上のプログラム（`deno`、`bun` など）。スクリプトは `args` に追加します |

**プロセスが動くタイミング。** 通常のモジュールは最初のコマンドで起動し、そのまま動き続けるので、2 回目以降のコマンドにはすぐ応答します。`resident = true` のモジュールはアイランドと一緒に起動します。モジュールがオフにされたとき、マニフェストが変更されたとき、アイランドが終了したときにプロセスは停止されます。

**終了のしかた。** `stdin` の EOF は、コアが終了したか、モジュールを停止したことを意味します。モジュールも終了してください。3 秒経ってもまだ動いているプロセスは、コアが強制終了します。

**環境変数：**

| 変数 | 値 |
| :--- | :--- |
| `POLYNYA_MODULE` | モジュールの id |
| `POLYNYA_LANG` | UI の言語：`ru`、`en`、`zh`、`ja` |
| `POLYNYA_API` | コアのプロトコル バージョン |
| `POLYNYA_VERSION` | Polynya のバージョン |

コアは `PYTHONUNBUFFERED`、`PYTHONIOENCODING=utf-8`、`PYTHONUTF8` も設定するので、Python のモジュールが自分で設定する必要はありません。

**出力。** `stderr` に書いた行はすべて Polynya のログに記録されます。プロセスがクラッシュする（終了コードが 0 以外になる）と、`stderr` の最後の行を載せたチップがユーザーに表示されます。10 秒以上動いた後にクラッシュした `resident` モジュールは再起動されます。`stdout` のうち正しいメッセージでない行は理由とともにログに記録され、読み取りは続きます。

**`hooks = true`：** モジュールがオンになるとコアは `exe register` を 1 回呼び、オフになると `exe unregister` を呼びます。モジュールはこの呼び出しを使って、ほかのプログラムの設定に自分のフックを追加します（内蔵の `agents` モジュールはこの仕組みで動いています）。

## 4. プロトコル

各メッセージは `\n` で終わる **1 行の JSON** で、UTF-8 でエンコードします。`op` フィールドがメッセージの種類を表し、未知のフィールドは無視されます。1 行書くごとに `stdout` をフラッシュしてください。そうしないとメッセージがバッファーに残ったままになります。

### コアから：`stdin`

| メッセージ | 届くタイミング |
| :--- | :--- |
| `{"op":"invoke","command":"convert","source":"hotkey","query":"","selection":"font-size: 16px","clipboard":"#fff"}` | `main` または機能の実行。`source` は呼び出し元で、`menu`（`command` 付きの行）、`search`、`hotkey` のいずれかです。`query` は検索欄のテキストです。`selection` はアクティブなアプリで選択中のテキストで、`selection = true` の機能をホットキーで実行したときだけ入り、何も選択されていなければ空です。`clipboard` は常にクリップボードのテキストです。何から始めるかはモジュールが決めます。 |
| `{"op":"select","id":"r1"}` | `item`、`toggle`、`button` の行が選ばれたとき（Enter またはクリック）。`command` 付きの `item` は代わりに `invoke` を送ります。 |
| `{"op":"submit","id":"query","text":"16px 24px"}` | `input` の行で Enter が押されたとき。 |
| `{"op":"closed"}` | モジュールのドロップダウンが閉じたとき。Esc、外側のクリック、ほかのパネルを開いたときなどです。 |

### コアへ：`stdout`

| メッセージ | 動作 |
| :--- | :--- |
| `{"op":"open","screen":{...}}` | この画面でモジュールのドロップダウンを開きます。検索からコマンドを実行した直後なら、結果一覧の代わりに検索の 1 ページになります。それ以外の場合は検索ブロックの下に開きます。`"at":[left,right]`（画面のピクセル）を付けると、タスクバーのその範囲の下に開きます。 |
| `{"op":"push","screen":{...}}` | 開いているドロップダウンで次の画面に進みます。「戻る」ボタンが付きます。 |
| `{"op":"update","screen":{...}}` | 現在の画面をその場で置き換えます。選択中の行と入力中のテキストは `id` によって同じ行に保たれます。入力に合わせて変わる結果や、刻々と変わる値に使います。 |
| `{"op":"close"}` | ドロップダウンを閉じます。それがコマンドへの応答だった場合は、コマンドを呼び出したウィンドウにフォーカスが戻るので、ユーザーはすぐに貼り付けられます。 |
| `{"op":"copy","text":"1rem"}` | テキストをクリップボードに入れます。 |
| `{"op":"chip",...}`、`{"op":"dismiss",...}` | 通知のチップ。[チップ](#6-チップ) を参照してください。 |

**コアが自分で処理すること：** 矢印キーでの移動、ホバー、長い行のスクロール、「戻る」（モジュールには通知されないので、行の id は画面をまたいで一意にしてください）、Esc、外側のクリックで閉じる動作、幅で切れた行の全文を見せるツールチップ、そしてスクリーン リーダー（名前、役割、状態は行そのものから取られるので、モジュール側で追加の対応は要りません）。

検索やホットキーからの **`invoke` の後**、コアはモジュールの応答を最大 1 秒待ってから検索を閉じます。処理だけを行うモジュール（コピーしてチップを出すなど）は `close` で応答します。メニューから呼ばれた機能は、ふつう `push`（「戻る」付きの次の画面）で応答します。

## 5. 画面

```json
{"title": "可変サイズ", "rows": [
  {"type": "input", "id": "sizes", "text": "16px 24px", "placeholder": "2 つのサイズ"},
  {"type": "divider"},
  {"type": "item", "id": "r1", "text": "clamp(1rem, 0.8333rem + 0.7407vw, 1.5rem)", "hint": "clamp()"}
]}
```

`title` は省略できます。タイトルがある画面や戻り先がある画面には、「戻る」ボタン付きのタイトル バーが付きます。

| `type` | フィールド | 内容 |
| :--- | :--- | :--- |
| `item` | `id`、`text`、`hint?`、`command?`、`keys?`、`confirm?` | 選択できる行。`hint` は右側に控えめに表示されます。`command` を付けるとその行はモジュールの機能になり、コアは細い列に機能のホットキーを表示し、`select` の代わりに `"source": "menu"` の `invoke` を送ります。`keys` はモジュール自身のものではないショートカット（例：`Win+L`）を表示するためのものです。`confirm`（例：`"今すぐ再起動しますか？"`）があると、最初に押したときにその質問と縮んでいくバーが表示され、3 秒以内にもう一度押したときだけ実行されます。 |
| `toggle` | `id`、`text`、`on` | スイッチ付きの行。押すと `select` が送られ、モジュールは新しい `on` を含む `update` で応答します。 |
| `input` | `id`、`text`、`placeholder?` | テキスト入力欄。押すとマウスの位置にカーソルを置いて編集が始まります。ドラッグで選択、ダブルクリックで単語を選択でき、長いテキストはスクロールし、クリップボード、`Ctrl+Z`、IME が使えます。Enter で `submit` が送られ、Esc でキャンセルされます。`text` は現在の値です。 |
| `button` | `id`、`text`、`plain?` | 横幅いっぱいのボタン。`plain: true` にすると背景なしで描かれます。 |
| `text` | `text` | 控えめな段落。`\n` で改行します。 |
| `divider` | | 細い線。 |
| `section` | `title` | 行のグループの上に置く小さな見出し。`title` が空なら余白になります。 |
| `header` | `title`、`subtitle` | 大きなタイトルと、その下の説明文。 |
| `pair` | `label`、`value` | 左にラベル、右に値。 |
| `art` | `lines`、`colors?` | 中央に置かれる等幅のテキスト アート。`colors[行][文字]` で文字ごとに `#rrggbb` を指定し、空文字列なら文字色になります。 |

どの行でも長いテキストは幅に合わせて切り詰められ、選択中の行ではマーキーで流れます。

## 6. チップ

チップはタスクバー右側のゾーンに表示される通知です。モジュールは自分の `stdout` に書き込みます。ほかのプログラムは名前付きパイプ `\\.\pipe\Polynya-<SessionId>` に送ります（1 回の接続で 64 KB までの JSON メッセージ 1 つ）。コマンドラインからは `polynya push` を使います。

```json
{"op": "chip", "key": "build", "title": "ビルド完了", "body": "48 秒", "icon": "ok", "ttl_ms": 5000}
```

| フィールド | 既定値 | 説明 |
| :--- | :--- | :--- |
| `key` | *必須* | チップの id。同じ `key` のチップは古いものをその場で置き換えます。 |
| `title` | *必須* | チップに表示される短いテキスト。 |
| `body` | `""` | 詳細。ホバー時にマーキーで流れ、展開したチップでは全文が表示されます。 |
| `meta` | `""` | 展開したチップの下部に表示される小さな文字。発信元や時刻など。 |
| `icon` | `"info"` | `ok`、`fail`、`info`、`key`、`claude`、`agent`、または色付きの丸 `color:#rrggbb`。 |
| `ttl_ms` | `null` | 表示時間（ミリ秒）。チップが先頭に来た時点から数えます。`null` なら閉じられるか置き換えられるまで残ります。 |
| `animated` | `false` | アニメーションするアイコン。処理が進行中であることを示します。 |
| `source` | `key` | シリーズ。同じ発信元のチップはキューで互いを待ちません。 |
| `popup` | `false` | チップが先頭に来たときに、コンパクトなドロップダウンとして展開します。 |
| `swatches` | `[]` | 展開したチップに表示する `#rrggbb` の色。クリックでコピーされます。 |
| `mark` | `null` | `swatches` 内で強調表示する色のインデックス。 |

`{"op": "dismiss", "key": "build"}` でチップを消せます。キューとシリーズのルールは **[通知](notifications.md)** で説明しています。

## 7. Rust 向け：`proto` クレート

リポジトリの `proto` クレートには、すべてのメッセージ（`ModIn`、`ModOut`、`Screen`、`Row`、`Msg`）の `serde` 型と、いくつかのヘルパーがあります。

* `proto::send(&msg)` はメッセージをパイプに送り、パイプが使用中なら短く再試行します。アイランドが起動していなければ、すぐにエラーを返します。
* `proto::language()` は UI の言語を返します。`POLYNYA_LANG`、`config.ini`、Windows の言語の順に調べます。
* `proto::info!`、`warn!`、`error!`、`debug!` は共有ログに 1 行書き込みます。各行は 1 回のシステム コールで書かれるので、異なるプロセスの行が混ざることはありません。
