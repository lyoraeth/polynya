# 通知、AI エージェント、ターミナル

[English](../notifications.md) · [Русский](../ru/notifications.md) · [简体中文](../zh/notifications.md) · **日本語**

Polynya には、すべての発信元が共有する 1 つの通知スタックがあります。コアの内蔵インジケーター、AI エージェント、ターミナルのバックグラウンド コマンド、外部スクリプト（`polynya push`）、サードパーティ モジュール、そして Windows 自身のシステム通知です。

---

## 1. キュー、シリーズ、「+N」の束の仕組み

アイランドの右側ゾーンは、頻繁な状態更新が新しい通知を覆い隠したり画面をちらつかせたりしないよう、厳密なルールで動きます。

* **先頭の位置と最短表示時間（3 秒）。** 新しい通知（または同じ `key` による既存通知の更新）は、アイランドのメイン ブロックにいちばん近い先頭に立とうとします。先頭に立った通知は、その位置を**最低 3 秒**保ちます。その間に*別の*発信元から通知が届くと、それは見えない状態で順番を待ちます。
* **賢いシリーズ（`source`）。** 同じ発信元（`source`。Windows のトーストでは「アプリ + タイトル」、つまりメッセンジャーの特定の会話）からの通知は、キューで互いを待ちません。
  * 同じシリーズの新しいメッセージはすぐに先頭に立ち、直前のものはただちにスタックへ移ります。
  * その発信元の通知がすでに見えない待ち行列にあった場合、新しい通知がその位置を引き継ぎ、古いほうはすぐにスタックへ移ります。
  * 別の発信元がすでに待っている場合、先頭チップの頻繁な更新（たとえば AI エージェントが「読み込み中」から「編集中」へすばやく変わる）では、3 秒の表示時間は**延長されません**。
* **公平な表示時間（`ttl_ms`）。** チップが消えるまでのカウントダウンは、通知が実際に先頭に立った時点から始まります。マウスがチップの上にある間やドロップダウンが開いている間はタイマーが止まり、カーソルが離れると改めて全期間で再開します。
* **チップ、展開表示、「+N」の束：**
  * 通常、チップはアイコンと短いタイトルを表示します。ホバーすると詳細がスクロール表示されます（複数行のテキストは ` · ` でつながれます）。
  * チップをクリックすると、全文、発信元、時刻、閉じるボタンを含むドロップダウンが開きます。
  * タスクバーの空き幅に収まらないチップは、アイコンの丸が並んだコンパクトなカウンター **「+N」** にまとめられます。「+N」にホバーすると隠れた通知のタイトルがスクロールし、クリックすると一覧全体が開きます。

## 2. AI エージェント（Claude Code、Codex、Cursor）

内蔵の `agents` モジュールは、ローカルの AI エージェントの作業状態をタスクバーに直接表示します。ブラウザーや別のウィンドウに切り替えていても、エージェントが何をしているかがわかります：*「思考中…」*、*「編集中 main.rs」*、*「応答待ち…」*、*「完了」*、*「エラー」*。エージェントの作業中はチップのアイコンが動きます（Claude 独自のグリフ、または 60° ずつ回転する Polynya のマーク）。

### 手動設定なしで動く仕組み
`agents` モジュールを有効にすると、コアが `polynya-agents.exe register` を一度だけ呼び出します（無効にすると `unregister`）。モジュールは自分のフックを各エージェントの設定ファイルに慎重に書き込み、**既存の設定を上書きせず、キーの順序も保ちます**。

1. **Claude Code（`~/.claude/settings.json`）：** `UserPromptSubmit`、`PreToolUse`、`PostToolUse`、`Notification`、`Stop`、`SessionEnd` イベントのフックを登録します。Claude Code はフックを bash 環境で実行するため、実行ファイルのパスはスラッシュ（`/`）で書き込みます。
2. **Codex（`~/.codex/config.toml`）：** `notify` フィールドにハンドラーを登録します。
3. **Cursor（`~/.cursor/hooks.json`）：** `beforeSubmitPrompt`、`afterFileEdit`、`afterShellExecution`、`stop`、`sessionEnd` のフックを登録します。

`polynya-agents.exe` 自体は常駐しません。エージェントがイベントのたびに呼び出し、数ミリ秒でアイランドのパイプに JSON を送ってすぐに終了します（アイランドが起動していなければすぐに終了し、終了コードは常に成功です。モジュールのエラーでエージェントの作業を妨げてはいけないためです）。

## 3. ターミナルの長時間コマンドと Lock キー

* **ターミナルの長時間コマンド。** **Windows Terminal** や **VS Code** の統合ターミナルで時間のかかるビルドやスクリプトを始めて別のウィンドウに切り替えると、コマンドの終了時に、コマンド名、実行時間、結果（チェック マークまたはバツ）を含むチップが表示されます。例：`cargo build · 48 秒`。
  * PowerShell / bash / zsh 用のプラグインは不要です。フォーカスがターミナルのウィンドウから離れた瞬間に、ConPTY の子プロセス ツリー（`RegisterWaitForSingleObject`）を通じて自動的に追跡が始まります。`cargo build && cargo test` のような連鎖でも、最終的な通知は 1 つだけです。
  * ターミナルのウィンドウを見ている間にコマンドが終わった場合は、通知されません。
  * しきい値はメニュー（オフ / 10 / 30 / 60 秒）または `config.ini` の `terminal_notify` キーで設定します（既定は 10 秒）。
* **Caps Lock と Num Lock。** 切り替えは低レベルの Raw Input で追跡し（システム全体の入力を遅らせるグローバルなキーボード フックは使いません）、短い状態チップを表示します。

## 4. Windows のシステム通知（試験的な `notify` モジュール）

`notify` モジュールは、`UserNotificationListener` を通じてすべてのアプリのシステム トーストを取り込み、アイランドの共有スタックに追加します（システム通知は同時に最大 5 件、チップの表示時間は 10 秒）。新しい通知は、大きな標準の Windows バナーの代わりに、タスクバーから出るコンパクトなドロップダウン（5 秒間）で表示します。

このモジュールは、Windows 11 自体の 2 つの根本的な制約のため、意図的に**試験的**としており既定では無効です。

### 制約 1：パッケージ ID（インストール時に UAC が必要な理由）
Windows API の `UserNotificationListener` は、**パッケージ ID**（MSIX）を持つプロセスだけが使えます。
* ユーザーにコード署名証明書の購入や開発者モードの有効化を求めないよう、Polynya は署名なしの**スパース パッケージ `Polynya.Notify`**（約 25 KB、コアに内蔵）を使います。このパッケージは外部フォルダーにあるモジュールの実行ファイルを参照します。
* Windows 11 では、実行ファイルを含む署名なしパッケージの登録に一度だけ管理者の確認が必要です（ないとシステムはエラー `0x80073D2B` を返します）。
* 設定で **「インストール」** を押す（または `polynya notify-setup` を実行する）と、パッケージの登録のためだけに UAC が求められ、アイランド自体は通常ユーザーのまま動き続けます。モジュールを無効にすると、パッケージは管理者権限なしで自動的に削除されます。

### 制約 2：重複する Windows バナーの抑制（`ShowBanner`）
公開されている WinRT API には、「他のアプリのポップアップ バナーは隠し、通知は通知センターに残す」ための文書化された方法がありません（`SuppressPopup` は自分のトーストにしか効かず、`RemoveNotification` は通知をあらゆる場所から消します）。何もしなければ、すべてのメッセージが 2 回表示されます。まず標準の Windows のウィンドウで、すぐ続けてアイランドのドロップダウンで。

解決方法：
* モジュールは、ユーザーのレジストリ キー `HKCU\Software\Microsoft\Windows\CurrentVersion\Notifications\Settings\<AUMID>` で、対象のアプリについてだけ `ShowBanner = 0` を設定します。これは Windows の設定にある「通知バナーを表示する」スイッチとまったく同じものです。通知音はそのまま鳴り、メッセージ自体も通知センターに残ります。
* **実際に通知を送ってきたアプリだけを変更し**、元の値はバックアップに保存します（`%APPDATA%\Polynya\banners.txt` と `banners-restore.reg`）。以前に自分でそのアプリのバナーを Windows でオフにしていた場合、モジュールはそのアプリに触れません（ドロップダウンなしの静かなチップだけを表示します）。モジュールの動作中に Windows の設定でそのアプリのバナーを再びオンにした場合は、その選択が尊重され、モジュールはそのアプリから手を引きます。
* **4 段階の保護と自動ロールバック：**
  1. モジュールが通常どおり終了したとき、または設定で無効にしたときは、すべての `ShowBanner` の値をすぐに元に戻します。
  2. モジュールはコアのプロセスを監視しており、`polynya.exe` が終了するとレジストリを元に戻して自分も終了します。
  3. モジュール自体がクラッシュした場合は、コアがロールバックを行います。
  4. **突然の電源断や、タスク マネージャーで両方のプロセスが強制終了された場合に備えて：** `HKCU\...\RunOnce\PolynyaBanners` にバックアップを `reg import` するコマンドを書き込みます。次回のサインイン時に、Polynya を起動しなくても Windows 自身がすべてのバナーを復元します。
* モジュールに `ShowBanner` を変更させたくない場合は、設定の **「システムのバナーを非表示にする」** スイッチをオフにしてください（`config.ini` では `notify_banners = system`）。標準の Windows のトーストはそのまま残り、アイランドはそれをタスクバーのコンパクトなチップとして重ねて表示するだけになります。
